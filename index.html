开发者 API 的叙述更聚焦到实际场景价值：运维告警、内部审批、排班通知、活动提醒都能直接调用叮办的聚合通知渠道。

Token 认证隔离用户权限，接入更安全
支持 GET / POST，多渠道联合分发
api-example.js 
// 使用叮办 API 聚合发送通知
const response = await fetch('/api/User/notify', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer YOUR_TOKEN'
  },
  body: JSON.stringify({
    title: '系统告警',
    description: '服务器 CPU 使用率超过 90%',
    channels: ['wework_robot', 'dingtalk_bot', 'telegram']
  })
});

const result = await response.json();

认证方式

支持以下三种方式传递 Token，优先级依次递减：

Authorization: Bearer YOUR_TOKEN
X-User-Token: YOUR_TOKEN
X-Access-Token: YOUR_TOKEN

接口端点

POST /api/Auth/login
获取用户 JWT Token
Body: { "userName": "string", "password": "string" }
POST /api/User/notify

发送通知，channels 为可选，不指定则使用用户默认配置

{
	  "token": "JWT_TOKEN",  // 如使用 Header 认证可省略
